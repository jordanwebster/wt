# A4 — repair a canonical tree that lost its marker

## Automated evidence

`register_repair_restores_only_a_replaced_canonical_checkout` deletes the
canonical marker and a hash-owned file, then byte-compares `registry.json`
before and after repair and compares tree ID, phase, sync, verify, and resource
state. It also refuses another path and a second repair of the healthy tree.
`canonical_repair_transcript` exercises the built binary and snapshots doctor
and repair output.

## Demonstration

Retained capture: `captures/A4.txt`. Verbatim observed block:

```text
--- A4 ---
Doctor found 1 error, 0 warnings, 1 note
  error  TREE_REPLACED repo - tree phase is replaced
  next   run `wt register <ROOT>/repos/repo --label repo --repair`
  note   SESSION_BACKEND sessions - session backend is tmux
  next   set `session.backend` in `$WT_HOME/config.toml` to change it
```

Regenerate it exactly with:

```sh
env WT_PROOF_CAPTURE=A4 cargo test --quiet --test human_transcripts canonical_repair_transcript -- --exact --nocapture > .handoff/session-ux/captures/A4.txt 2>&1
```

## Gap

The automated case deletes the marker. A wrong marker derives the same phase
and repair branch but is not separately snapshotted. No test races a hostile
checkout replacement between gitdir validation and marker write.
