## Operator recipe

Build this branch, choose disposable clones of representative real repositories
(for example one Cargo repository and one Node or Python repository), and use a
scratch home:

```sh
cargo build --workspace
wt_bin="$PWD/target/debug/wt"
scratch="$(mktemp -d)"
export WT_HOME="$scratch/wt-home"

"$wt_bin" register /absolute/path/to/disposable-cargo-clone --label cargo-real
"$wt_bin" doctor cargo-real
"$wt_bin" new cargo-real/session-proof --no-attach
"$wt_bin" status cargo-real/session-proof
"$wt_bin" open cargo-real/session-proof --no-attach
"$wt_bin" close cargo-real/session-proof
"$wt_bin" remove cargo-real/session-proof --yes

"$wt_bin" register /absolute/path/to/disposable-second-clone --label second-real
"$wt_bin" new second-real/session-proof --no-attach
"$wt_bin" status second-real/session-proof
"$wt_bin" remove second-real/session-proof --yes
```

Inspect that backend resolution is announced only once, adapter seed behavior
matches the host filesystem, sync reports passed versus skipped honestly, and
session lifecycle commands agree with the final status. Use disposable clones:
`register` intentionally writes wt identity/exclude metadata into a repository.

## Gap

The recipe is not evidence until the operator runs it and retains its output.
It deliberately leaves scratch cleanup to the operator after inspection and
does not name or touch any existing operator checkout.
