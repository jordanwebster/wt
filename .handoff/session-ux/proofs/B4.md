# B4 — session decision matrix

## Automated evidence

`session_creation_and_attachment_matrix` is table-driven and runs one private
tmux server per row. Each row asserts session created?, client attached?, and
recording agent started? for terminal, no terminal, activation marker, JSON,
backend none, `--no-open`, `--no-attach`, and `session.attach = false`.

## Demonstration

Captured expected/observed matrix (all rows passed):

```text
row                   created  attached  agent-started
terminal              yes      yes       yes
no-terminal           yes      no        yes
activation            yes      no        yes
json                   yes      no        yes
backend-none           no       no        no
no-open                no       no        no
no-attach              yes      no        yes
attach-setting-false   yes      no        yes
```

Replay: `cargo test --test session_flow session_creation_and_attachment_matrix -- --exact --nocapture`

## Gap

Gap: the matrix exercises `$TMUX` switching separately through the tmux
abstraction contract; it does not nest the private test client inside a second
real tmux server.
