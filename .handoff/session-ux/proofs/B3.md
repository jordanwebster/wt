# B3 — agents start only on creation

## Automated evidence

`agents_start_only_for_new_sessions_and_open_all_resumes_recorded_agents`
uses an executable recording agent on a private server. It observes one
`start` for initial creation, no new event when opening the live session, no
event for `new --no-open`, a `resume` after closing and recreating the recorded
session, and no invocation in a separate shell-only configuration.

## Demonstration

Captured recorder sequence after `open --all`:

```text
start
start
resume
start
```

The first line is the original tree; the later lines are the unrecorded
canonical and second tree starts around the recorded tree's single resume.

Replay: `cargo test --test session_flow agents_start_only_for_new_sessions_and_open_all_resumes_recorded_agents -- --exact --nocapture`

## Gap

Gap: the concurrent `new-session` loser is covered by the implementation's
existing-session recheck but is not forced deterministically in the real-tmux
test.
