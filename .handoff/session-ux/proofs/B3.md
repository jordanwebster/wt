# B3 — agents start only on creation

## Automated evidence

`agents_start_only_for_new_sessions_and_open_all_resumes_recorded_agents` uses
an executable recording agent. It asserts one `start` on initial creation, no
new event on attachment to the live session, no event for `new --no-open`, one
`resume` for the recorded tree after recreation, and no event in a separate
shell-only configuration.

## Demonstration

Retained capture: `captures/B3.txt`. This line is emitted from the recorder log
after the assertions and is quoted verbatim:

```text
--- B3 ---
agent events: start, start, resume, start
```

Regenerate it exactly with:

```sh
env WT_PROOF_CAPTURE=B3 cargo test --quiet --test session_flow agents_start_only_for_new_sessions_and_open_all_resumes_recorded_agents -- --exact --nocapture > .handoff/session-ux/captures/B3.txt 2>&1
```

## Gap

The no-agent control uses a second isolated harness and log rather than
reconfiguring the first server. Concurrent `new-session` loser behavior is
covered by the implementation's recheck but is not forced in real tmux.
